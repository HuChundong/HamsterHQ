# 右侧面板（artifact panel）

[English](artifact-panel.md)

`packages/dsh-artifact-panel` 是一个纯浏览器的 dsh 插件：它在会话窗口右侧挂一块面板，租户在里面开工具、看 agent 产出的东西。本文说明它**是什么**、为什么长成这样，以及做它的过程中被逼出来的那些平台事实。

## 一句话

**一个 tab 只放两种东西之一：用户主动开的工具，或 agent 被动产出的结果。**

这句话是 tab 栏的裁决标准。任何一个想成为 tab 的东西，先问它是哪一类；两类都不是，就不成为平权 tab。服务某个表面的控制可以留在那个表面内部——电脑下方的定时任务管理就是一个——但不会因此再长出一个工作台 tab。

## 组织原则：主动与被动

面板里的 tab 按**来源**分成两类，这是整个产品形态的骨架。

**主动**——用户自己要用的工具，长期驻留：文件、终端、画布、浏览器，以及从会话标题栏打开的电脑。

**被动**——会话过程中 agent 产出的结果，用户查看：产出文件的预览（markdown / 代码 / 图片 / HTML）。

同类产品常见的失败模式是把所有面板做成**平权的 tab**：文件树、终端、Git、子代理、编辑器并排堆在一条 tab 栏里，没有任何原则说明谁该在那儿。一旦平权，加下一个就没有理由拒绝，面板最终长成一个什么都有的工作台。

主动/被动的二分给了拒绝的理由：**一个新 tab 要么是用户会主动去开的工具，要么是 agent 会产出的结果，两者都不是就不进这个面板。**

### 明确不做的

| 不做 | 理由 |
|---|---|
| Git 面板 | 既非工具也非产物，属会话叙事，归左侧 |
| 把子代理拓扑或通用后台作业做成平权 tab | 同上；电脑里的定时任务管理是该表面的控制，不是另一个 tab |
| 底部面板 / 拖拽分栏 / 跨面板合并 | 布局系统一旦引入就会长成 IDE，且自带一套持久化与陈旧状态清理 |
| 文件编辑 | 编辑器是 agent；人想改，说一句话比打开编辑器快 |
| Office / PDF 预览 | 依赖体积大、收益低，留到有人真的要 |

## tab 栏

**所有 tab 一律可开可关，包括文件。** 主动/被动是**判据**（什么东西有资格进这个面板），不是 tab 的行为差异——没有"固定 tab"这个概念。

- **宽度只跟自己的名字有关**，上限 132px。共享宽度（一排 tab 平分）和按比例压缩都试过，两者都让一个 tab 的宽度变成**其他 tab 的函数**：开第七个文件会让已经开着的六个一起变窄，用户正要点的那个 tab 不在他看的地方了。
- 名字放不下时**渐隐**，不用省略号：省略号要花三个字符说"还有"，而在这条栏的宽度上，三个字符往往就是名字的大部分。渐隐用遮罩作用在文字上（不是盖一层渐变色块），因为底色有三种（普通/悬浮/选中）× 两套主题。
- **关闭键叠加显示**，不占位：它只在指针悬停时出现，浮在名字尾部的"排水沟"上（label 的 14px 右内边距），所以不占用任何非活动 tab 的宽度。
- 装不下就**横向滚动**：滚轮（原生 `passive: false` 监听，React 的 `onWheel` 是 passive，里面 `preventDefault` 只会打印警告）、拖拽，以及"当前 tab 移出视野时自动滚回来"。
- **中键关闭**，和别处的 tab 一样。
- **按路径去重**：同一文件反复产出只占一个 tab。
- **不做自动淘汰**：tab 累积，由用户关。

选中态**只靠底色**区分，不用描边也不用字重。原因是量出来的：旧的选中底色对面板底是 1.12:1，而对**悬浮底色**是 1.005:1——正在打开的那个 tab 和指针正好停着的那个 tab，颜色相同到小数点后三位。字重也去掉了：500 比 400 量出来更宽，会让选中的 tab 变宽、把右边的 tab 全部推走。

`+` 按钮的行为分两种：面板里**一个 tab 都没有**时，它把面板切到空态（四张卡片：文件 / 终端 / 画布 / 浏览器）；**已经有 tab** 时，它从按钮下方掉出一个菜单直接列出四个工具——把面板切走等于"为了在旁边加一个东西，先把你正在看的东西拿走"。

## 面板本身的开关

- **无会话**（首页 / 新会话态）：窗口右上角一个按钮。
- **会话中**：标题栏左侧区域，与"轨迹"按钮相邻。

两处点击后都是打开面板；面板已开时按钮变为收起。**面板默认不存在**：会话产出第一个东西、或用户主动开第一个工具之前，右侧不占宽度——纯聊天的会话不该被一个空面板占掉三分之一屏幕。

## 电脑面板

电脑有两套布局，因为侧边栏和放大模式要解决的是两件不同的事。

在普通侧边栏宽度下，桌面放在内容最上方：一个保持原生 **1280:720** 比例的圆角卡片。宽度跟着可拖拽的面板宽度变化，高度由这个比例推导。这样 noVNC 缩放的是桌面，而不是用上下两块 letterbox 去填满一条很高的列。artifact panel 只声明一个空座位；`dsh-computer` 跟随它并把桌面渲染在面板的令牌表面上，亮色、暗色和部署皮肤仍然是配色的唯一来源。

卡片下方是定时任务管理本身，不是它的一份复制。`dsh-scheduled-tasks` 拥有列表、加载态、新建/编辑表单、启停和二次确认删除；`dsh-computer` 在桌面下声明它的带 data 属性空座位。由于面板本身是 body 上的一棵独立 React root，定时任务插件跟随这个座位并在上面挂自己的 root。`scripts/check-computer-layout.mjs` 跨三个插件锁住 panel 到 computer 的座位、computer 到 schedule 的座位，以及 1280:720 比例。

`dsh-computer` 还拥有 `computer_request_user_action`。agent 只在安全自动导航到尽头，遇到登录、MFA、验证码或授权同意这类必须由人完成的步骤时调它。运行中的工具行会变成带实时预览的三选项卡片：**接管**只打开这个 Computer 面板，不结束等待；**我完成了**与**跳过**回答 DSH 公开的 `userQuestions` 请求。随后工具在同一轮继续，并递延一条携带结果的 plugin 来源上下文消息，而不是在用户的输入框里伪造文字。工具说明也明确禁止要求用户在聊天中粘贴密码、验证码或其他秘密。

面板放大时不渲染任务座位，桌面重新占满剩余高度。放大是为了操作机器；恢复侧边栏后，紧凑卡片和任务列表回来。两种结构使用同一个 noVNC URL，所以布局切换没有定义第二套桌面协议。

## 被动这一半几乎不用我们渲染

dsh 的 `ui-deliverables` **已经**在每轮末尾渲染了产出文件的 chip 行。我们不自己算产出、不渲染任何列表——只把点击接管过来。

接管点是 `ctx.remote.session.openWorkspacePath`：对话里所有文件打开都汇入这一个生成的 Remote 方法（工具行的路径链接、产出文件 chip、正文里的文件提及，都由 `ui-chat` 解析成绝对路径后调它），而它默认把文件交给宿主操作系统。在无桌面的沙箱里，这会变成 `spawn xdg-open ENOENT`。

生成的 Remote 方法是可配置的 getter 属性。直接赋值在严格模式下会抛错，在非严格模式下则会静默保留原 transport getter，所以包装层必须替换属性描述符，并在卸载时原样还原：

```js
const descriptor = Object.getOwnPropertyDescriptor(sessionRemote, 'openWorkspacePath')
const original = sessionRemote.openWorkspacePath
Object.defineProperty(sessionRemote, 'openWorkspacePath', { value: wrapped, configurable: true })
// 卸载时：Object.defineProperty(sessionRemote, 'openWorkspacePath', descriptor)
```

包装层收到绝对路径后，返回与 Host 接受打开请求时相同的成功 Remote 结果，再打开面板 tab。这样既维持了 `ui-chat` 的调用约定，也不会把请求送到原生打开器。

**接管不了就必须放行。** 请求没有绝对路径时，包装层要原样调用 `original`，而不是吞掉这次调用，让不在面板契约内的输入继续得到 harness 自己的校验与行为。

轮末尾还是一条带优先级的渲染链，可以抢在 `ui-deliverables` 之前渲染自己的 chip 行。**我们不这么做**：既然 `openWorkspacePath` 已经被包了，原生 chip 点下去就已经进面板，替换那行 UI 只会多一处对上游渲染结构的耦合。

### 联动规则

1. **一个入口，多个来源**。产出文件 chip、工具行的路径链接、正文里的文件提及，全都汇入同一个方法，因此全都自动获得同样的行为。
2. **面板关着就打开它**。用户点了文件却什么都没发生是最糟的结果。打开面板、开 tab、聚焦，一次完成。
3. **按路径去重**。同一文件重复点只聚焦已有 tab。
4. **viewer 由扩展名/MIME 选**，选不出来的落到"下载"兜底，不留空白 tab。
5. **会话切换时换掉整组 tab**。tab 属于会话，不属于窗口。
6. **不抢焦点**：只有用户点击才开 tab，agent 产出本身不触发任何面板动作。

第 6 条是"被动"的定义本身，前 5 条是让它不难用。

### 产出信号的语义

dsh 的会话快照里，`tool-result` 节点带一个 `callView`：

```
{ card: 'diff' | 'generic', kind: 'edit', locations: [{ path }] }
```

`ui-deliverables` 据此决定什么算产出：**只有渲染意图为 diff 卡或 edit 型 generic 卡的工具结果才算，读取、删除、失败一律不算**，并在轮边界重置累积。

它的盲区是 `bash: python gen.py > report.html` 这类经由 shell 产出的文件——tool-result 不带 edit 卡，不计入产出。用 fs.watch 补上的方案被否掉了：那需要一整套忽略清单和排序启发式，用面板 80% 的复杂度换 20% 的场景。真需要时，那条路径本来就渲染在对话里，点一下就打开。

## 数据平面：走 envd，插件因此没有 host 半

文件平面走 envd，不走隧道：envd 的接口已经完备，不需要在沙箱里再实现一遍。

这个选择有一个连带效果，比接口完备本身更值钱：**插件不需要 host 半了。** 因为 envd 是网关从沙箱外部寻址的（`Host: 49983-<sandboxId>.<domain>` 经 CubeProxy），而 dsh 插件的 host 半跑在沙箱**内部**——让内部进程绕出去再绕回来毫无意义。所以数据平面是：

```
浏览器 → 网关 /sandbox/fs/*  →  CubeProxy  →  envd
```

网关侧本来就有 `callerOf(req)` 解析调用者、`sandboxes.ensure(username, caller.id)` 拿 `sandboxId` 的现成路径，不经过隧道。于是不需要 `connection.rpc.handle` 通道、不需要 cordis host 插件、不需要给 dsh 的新通道加 nginx location。`packages/dsh-artifact-panel` 因此是一个**纯浏览器包**，envd 的调用全部落在 `gateway/src/envd.js`。

额外收益：面板在 dsh 后端还没起来时也能工作（envd 与后端存活无关），冷启动时租户能先看见工作区里已有的东西。

四个主动 tab 有三个落在 envd 上：文件树用 `ListDir`，预览取文件用 `GET /files?path=` 加 `Stat`，终端用 envd 的 PTY 服务（这条要求 `envd.js` 有一条流式路径，并在网关开一个 WebSocket 端点桥接——`envdRequest` 一次性解码完整 body，长连接会阻塞到超时）。走 envd 的 PTY 意味着**沙箱里不需要装任何原生终端依赖**。

第四个落不上去：浏览器观察读的是 CDP，而 CDP 只监听沙箱自己的回环——这是故意的，那个端口能以租户身份操纵浏览器——envd 又不转发 TCP。所以这一个 tab 走 `dsh-computer` 注册的 `/browser` 通道，经隧道过来。面板包依旧是纯浏览器包；宿主半边属于那个拥有 agent 与人共用浏览器和桌面的插件。

### 画布不是浏览器

第三个主动 tab 一度设想为"浏览器"（看 agent 起的 dev server，或上外网），最终改成**画布：看 agent 正在做的页面**。

这不是把它做简单了，是把它挪回了判据那条线上：dev server 浏览器是背后拖着一台机器的**工具**，而画布就是**产出本身**。代价上差整整一个数量级——反向代理、泛域名证书、绝对路径重写、WebSocket 转发、出口边界，那些全部只为伺候一个 dev server；静态页面一个都不需要，而画布要的 `/sandbox/preview/<票>/<路径>` 已经建好了。

两个已定的取舍：

- **允许联外网**。CSP 只有 `sandbox` 指令（拿掉同源），不限制 `script-src`／`connect-src`，所以 agent 写的页面可以引 CDN 上的图表库。这是明确选择——收紧它会直接限制 agent 能产出什么。
- **画布内部跟随**。它每两秒问一次哪个页面最新、有没有被改写，变了就重载。这是对"不抢焦点"的**故意破例**，但破得住：打开画布这个 tab 本身就是用户在说"把你在做的东西给我看"。它仍然不会自己弹开面板，也不碰任何别的 tab。跟随用的是**最近修改时间**而不是产出信号，因为后者的盲区恰好在画布输不起的地方（shell 重定向产出的页面永远不在那条信号里）。

### 浏览器 tab 是一扇窗，不是那个浏览器

第四个 tab 看起来像上一节否掉的东西，但不是。当年否掉的是一个**可交互**的浏览器——反向代理、泛域名证书、路径重写、出口边界，那整套机械都是为了让人亲手操作沙箱里跑着的页面。而这个 tab 是一次**观察**：agent 用自己的 CLI 在沙箱里开着一个无头 Chromium 干活，没有这个 tab，那些活是不可见的——对话里命令一条条成功，命令作用的页面却哪里都看不到。

所以这个 tab 只展示 agent 的浏览器正在展示的东西：约一秒一次向沙箱要一张页面的 JPEG 画出来，旁边列出打开的页面。故意做成只读——人和 agent 共用一双浏览器的手是打架，不是功能——这也是 dev server 那套机械一件都不用回来的原因：请求应答通道上的一张轮询图片，没有点击、没有键入、没有代理。只有 tab 在显示、窗口可见时才要帧；关掉 tab，沙箱一分钱都不花。

## 两条必须做对的路径约束

**一、只能传绝对路径。** `Dockerfile` 里的 `ENV HOME` 是容器环境变量，不是 `/etc/passwd` 里 root 的 home；envd 解析相对路径靠 passwd，`path=notes.md` 会落到 `/root/notes.md`。网关直接拒绝相对路径，不做猜测性拼接。会话 cwd 的解析放在客户端——`ctx.sessions` 里有每个会话的 `cwd`，相对路径在浏览器侧先解析成绝对路径再发给网关。

**二、路径钉在工作区（`/mnt/workspace`）之内，但这是"范围"不是"防线"。** 真正的安全属性只有一条，而且不在路径处理里：**`callerOf` 解析调用者、`sandboxes.ensure` 交回的是那个调用者自己的沙箱**，所以一个请求只可能打到发起它的租户自己的机器上。跨租户读取不是"被防住了"，是无法表达。

沙箱内部没有什么需要防的：边界就是沙箱本身，租户在自己的沙箱里已经是 root，agent 就是一个他们能打字进去的 root shell。所以这个根的作用是让它成为一个**工作区浏览器**而不是文件系统浏览器。

**因此软链不追。** 早先的版本对每个路径做 `realpath` 再校验，买不到任何安全性（同一份内容跟 agent 说一句话就能拿到），却在每个请求上多一趟往返，而且行为是错的：租户故意把自己的目录链进自己的工作区，本来就该能打开。

前缀比较本身要写对：归一化分隔符、去掉尾斜杠、要求 `t === b || t.startsWith(b + '/')`——裸 `startsWith` 会放行 `/mnt/workspace-evil`。

## HTML 预览：同源加 CSP sandbox

不需要给预览一个独立 origin。同源路径前缀配合响应头就够：

```
content-security-policy: sandbox allow-scripts allow-popups allow-downloads allow-modals; object-src 'none'
x-content-type-options: nosniff
referrer-policy: no-referrer
```

`sandbox` 指令**不含 `allow-same-origin`**，浏览器强制给它一个不透明源。iframe 的 `sandbox` 属性是第一道边界，这个头是纵深防御——即使被弹窗顶层打开也守得住。

预览 URL 必须用**路径编码**而不是查询参数：查询编码会在浏览器解析相对路径时丢掉会话 scope，被预览页面的 `./style.css`、`img/x.png` 就会 404。

## 怎么挂上去：body 级 portal

**整面板 slot 由 `ui-layout` 独占**，插件拿不到。所以面板自己挂一个 body 级宿主，用自己的 React root 和 fixed 定位。这不是权宜之计，是这个平台上唯一的路。随之而来的约定：

- **根锚点带 data 属性**，皮肤和外部 CSS 靠它做作用域覆盖；
- **布局变量写在 `<html>` 上**，面板打开时有效，拖拽期间逐帧更新；
- **z-index 压在宿主浮层栈之下**：DSH 的浮层在 100 / 1000+，面板取 40 一档，任何弹窗天然盖住面板；
- **类名不是契约**：CSS Modules 哈希会变，需要精确命中时用 `[data-dsh-artifact-panel]` 属性选择器。

还有一条互斥：`dsh-web-ui` 家族有一个 `aionui-panel` 右面板提供方，它被选中时面板必须整个不挂载，否则两个面板叠在一起。**这个判定必须是活的**——用户是在设置里切换提供方的，切换的那一刻两个面板就叠上了；订阅运行时的 `settings/document-updated` 广播重新求值并 `unmount()`，拿不到 `remote` 服务的部署退化成启动时判定。

面板宽度与折叠状态存插件自己的设置里。**首屏要在第一次挂载前把偏好读出来**，否则新会话会先按默认宽度画一帧再跳；但读设置不能无限等——设置路由挂了面板就永远不出现了，所以用一个两秒超时去赛跑，超时退回默认值，面板照常挂载。

## 平台硬约束

- **构建纯度门**：client bundle 禁止 value-import `@dsh-external/*` 和非白名单的 `@deepseek-ai/*`；`import type {}` 会被擦除，不触发。
- **ModuleLoader 不跨插件**：绝不 `require` 对方模块。跨插件表面必须有明确归属的契约——行为跨边界时走方法；一个插件在另一个插件的布局里负责渲染时，走定时任务管理所用、且有检查锁住的 data 属性座位。
- **皮肤是令牌驱动的**：只消费 `--dsw-alias-*` / `--dsw-font-*` / `--ds-*`，不硬编码颜色。特别地——**绝不消费 `--dsw-specific-sidebar-fill`**，那是宿主左侧导航列的专属令牌，有皮肤把它设成 `transparent`；面板表面用 `--dsw-alias-bg-layer-1`。
- **令牌名必须核过才能用。** 在真实浏览器里确认该名在 `body` 上是已定义的 CSS 自定义属性。已知可用的是 `--dsw-alias-interactive-bg-hover`（悬浮）和 `--dsw-alias-button-ghost-active-fill`（按下）。**核过之后不要写字面回退值**，它只会掩盖下一个缺失的名字。
- **半透明表面要回退**：文本类表面读到 alpha < 0.9 的玻璃值时回退不透明底色，否则文字会叠在皮肤背景上滚动。这个回退**不能**靠 `读令牌() || 兜底` 写——`transparent` 和 `rgba(...,0.16)` 都是真值字符串，`||` 永远不触发。
- **对齐宿主外观时只使用已文档化的主题令牌**（`--dsw-alias-*`、`--dsw-font-*`、`--ds-*`）。不要抄计算样式，也不要把哈希过的 CSS-module 类名当契约。
- **i18n 跟随 `ctx.locale`**，不是浏览器语言。
- **有构建步骤，且只为一件事**：终端需要一个渲染器，xterm 从包内打包进来（`build.mjs`）。React 等宿主已提供的东西不打包——源码里的 `require('react')` 是 `__ModuleLoader__.load` 传进来的局部绑定，打包器不碰它。

## 沙箱里有什么，没有什么

- `/app/sandbox/env.sh` **不敏感**：它是 [`Dockerfile`](../Dockerfile) 末尾的白名单投影，从镜像的 `ENV` 值写出。名单以那份文件为准，本文不另列一份会过期的子集。
- `/proc/<后端pid>/environ` 里有 `MODEL_API_KEY` 和 `SANDBOX_TOKEN`。在 CubeSandbox 下前者是**占位符**——真实密钥由出网策略在请求离开时注入，从不进入沙箱（见 [`design.zh.md`](./design.zh.md) 的"模型平面"）。租户本来就能 `printenv` 读到环境里的一切，所以面板不为此设防；它防不住的东西，`printenv` 也拿得到。
